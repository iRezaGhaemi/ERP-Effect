داشبوردها و گزارش‌ها همراه ماژول‌های داده‌ساز خود تکمیل می‌شوند. کامنت تسک و اعلان سیستمی پیام‌رسان نیستند و حفظ می‌شوند. جزئیات هر ماژول در زمان شروع آن و بر اساس قراردادهای واقعی مرحلهٔ قبل مشخص می‌شود؛ این جدول ادعای پیاده‌سازی ماژول‌های آینده نیست.

## قاعدهٔ تحویل

هر مرحله باید migration، API، صفحهٔ متصل، کنترل دسترسی، تست و مستندات لازم داشته باشد. تست‌های داده‌ای فقط روی دیتابیس موقت اجرا می‌شوند. SHA محلی و SHA تأییدشدهٔ remote در همین گزارش ثبت می‌شوند. شکست push به معنی تحویل موفق نیست و جداگانه گزارش می‌شود.

## تحویل حذف پیام‌رسان

- ماژول، ورودی build، ناوبری، RBAC، route، داده و استایل پیام‌رسان، اشتراک تسک در چت و عملیات پیام پروفایل حذف شد.
- کامنت تسک، اعلان سیستمی و آیکن مشترک موردنیاز آن‌ها حفظ شد.
- build، شش regression، smoke همهٔ مسیرها و جریان‌ها، leak-check در ۴۱ نما و مجموعهٔ کامل QA مرورگر پاس شدند؛ QA مرورگر شامل containment در چهار viewport، آزمون‌های v2.3 تا v2.6 و آزمون نهایی ۲۰/۲۰ بود.
- بازبینی task، بازبینی اصلاح QA و بازبینی نهایی بدون ایراد باز Critical/Important بسته شدند.
- commitهای این تحویل: `d1d4a17` (حذف)، `2241398` (همگام‌سازی QA با ماژول‌های واقعی) و `0bb1515` (پاک‌سازی artifact داخلی).

## وضعیت پیش از مرحلهٔ ۱

- commit طراحی احراز هویت: `dea4ba3`؛ همراه تحویل حذف پیام‌رسان push می‌شود.
- اصلاح healthcheck توسعه در `compose.yml` و تست‌های `tooling/smoke/` از اجرای محلی قبلی باقی است و نباید از بین برود؛ در پذیرش مرحلهٔ ۱ بازبینی و ثبت می‌شود.
- کاربران/نقش‌ها/نشست/audit پیاده‌سازی اولیه دارند. بقیهٔ ماژول‌ها هنوز دمو هستند.
- تصمیم حذف پیام‌رسان، اسناد تاریخی قبلی را برای این فیچر منسوخ می‌کند؛ تاریخچهٔ Git حذف نمی‌شود.

## تحویل مرحلهٔ ۱

- OTP و وابستگی‌های SMS از مسیر اجرایی، API، UI و تست‌های فعال حذف شدند؛ migration نهایی داده‌ها و جدول‌های OTP را بازنشسته می‌کند.
- ورود نام‌کاربری/گذرواژه، تغییر اجباری اولین گذرواژه، بازنشانی مدیر، لغو نشست‌ها، قفل حساب، rate-limit، RBAC و audit به PostgreSQL واقعی متصل هستند.
- ساخت کاربر با گذرواژه اولیه، مدیریت نقش و override، صفحات کاربران/نقش‌ها/نشست‌ها/audit و فرمان امن `reset-admin` تکمیل شدند.
- migration و seed تکرارپذیر، کاربر runtime کم‌دسترسی PostgreSQL، Docker/Compose، healthcheck، CI و OpenAPI تحویل شدند.
- `lint`، `typecheck`، unit، integration، API E2E (۲۴/۲۴)، build تولید، smoke و QA کامل Chromium پاس شدند. OpenAPI پس از تولید مجدد بدون drift بود.
- اجرای کامل Compose روی دیتابیس خالی و فلو واقعی Playwright در پذیرش همین تغییرات پاس شده است. بازاجرای نهایی imageها را ساخت، اما کمبود فضای میزبان Docker پیش از ایجاد کانتینر خطای زیرساختی داد؛ برای جلوگیری از توقف کانتینرهای نامرتبط کاربر، Docker Desktop مجدداً راه‌اندازی نشد.
- commit تحویل: `4c3ad42b526f279fe0c9e260526860380212c9ca`؛ SHA محلی و شاخهٔ remote `codex/foundation-identity` پس از push دقیقاً یکسان تأیید شدند.
